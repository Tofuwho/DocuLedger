# IMPLEMENTATION_PLAN.md — DocuLedger PH

## 1. Project Overview & Architectural Guardrails
**DocuLedger PH** is an automated Philippine document-to-ledger extraction and compliance audit web application. It converts digital supplier **Sales Invoices**, **Purchase Orders (POs)**, and **BIR Form 2307** certificates into verified, accounting-ready ledger entries.

### Core Engineering Constraints
* **Tech Stack:** Python 3.11+, Django 5.2, Django REST Framework (DRF), `PyMuPDF` (`fitz`), `Pydantic` v2, PostgreSQL (Supabase-compatible, with SQLite fallback for local dev/CI), and modular Vanilla JavaScript + HTML5/CSS3.
* **Lightweight Runtime:** Do **not** install heavy local ML/OCR libraries (`torch`, `easyocr`, `paddleocr`, `tesseract`). All PDF parsing uses `PyMuPDF` (`fitz`) spatial text/coordinate extraction paired with schema-enforced LLM API extraction.
* **Offline/Demo Resilience:** Include a deterministic fixture/parser fallback when `OPENAI_API_KEY` or `GEMINI_API_KEY` is unset so the 1-click recruiter sandbox and `pytest` suite run with zero external API dependencies.
* **Financial Precision:** All monetary calculations and tax validations **must** use Python's `decimal.Decimal` (`ROUND_HALF_UP`). Never use `float` for currency.
* **Zero-Login Recruiter Sandbox:** The root route (`/`) loads directly into a live interactive workspace pre-stocked with 3 Philippine sample PDFs and a "1-Click Extract & Audit" workflow—no registration or login required.
